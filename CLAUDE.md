## What this repository is

- A per-card Hidden Markov Model fraud-detection **server** for test and development, written in
  C# by Claude. It is not a WinUI app: there is no MSIX, no window, and no signing for now.
- **README.md is the specification.** Requirement IDs (`SM-PRIV-001` and so on) are stable. Change
  the README in the same pull request as the behavior.
- Two run modes (README §1): **Home** (Kestrel, local folders), built and verified first, then
  **Azure** (App Service Linux, Blob Storage).

## Layout

- `src/SecretModel.Core`: tokenizer, quantizer, token validation, HMM, scorer, the profile and
  history files, the `IModelStore` and `IHistoryStore` interfaces, the Home-mode `FileModelStore`
  and `FileHistoryStore`, the journal file reader, and Home-mode ingestion (`FolderJournalSource`,
  `JournalIngestor`, `FileAuditLog`). No ASP.NET, no Azure.
- `src/SecretModel.Api`: ASP.NET Core host, certificate authentication, the Azure Blob model store.
- `tests/SecretModel.Tests`: MSTest tests.
- `tools/SecretModel.Synthetic`: synthetic shoppers and anomalies (made-up data) for tests, the study and the harness.
- `tools/azurite`: the pinned Azurite emulator (`package.json`, `package-lock.json`) and `wait-for-port.mjs`, for the Blob store tests only.
- `tools/SecretModel.ScoringStudy`: the measurement behind README §7.1; its output lives in `docs/studies/`.
- `reference/python`: the Meta AI prototype. **Read-only.** Never edit it; its attribution stays.
  `PROVENANCE.md` there lists every file's hash.

## Privacy rules (never break these)

- No identifier in `src/` may name a PAN-bearing concept: `pan`, `card_number`, `cardholder`, `cvv`,
  `expiry` (SM-PRIV-006).
- Never log or echo a value that failed token validation (SM-PRIV-004, SM-PRIV-005).
- The tokenization vault secret never goes to the server (SM-OPS-003).
- Test data is synthetic only. Use published test PANs (such as `4111111111111111`) only as
  inputs to tests that check they are rejected or tokenized.

## Testing rules

- Every requirement gets at least one test that can fail (SM-VER-001 to SM-VER-005).
- A test is not counted until it has been seen failing with the behavior deliberately broken.
  Record how it was broken in the pull request.
- Never weaken, skip or delete a test to make it pass. Never change a known-answer test's expected
  values. Golden vectors come from `reference/python`, from published sources, or from an
  independent exhaustive computation in exact arithmetic (`tools/golden`), and are cited in the
  test file. Never from the C# being tested.
- Locked file formats live in `docs/formats/`, each with a byte-for-byte known-answer test.
- Report where each test ran: Claude's cloud Linux workspace, CI, or Edwin's PC.

## Never commit

`.pfx`, `.pem`, `.key` and `.cer` files; anything with a private key; `appsettings.*.local.json`;
connection strings; thumbprint allowlists for real deployments; Azurite data folders; generated
test journals larger than a small fixture.
